# 自動分類

「這個模組伺服器要不要裝」是轉換的核心問題。SideShift 從多個來源收集證據，
按可信度取最可靠的一條作為結論——**沒有任何依據時絕不猜**。

## 證據從哪來

按可信度從高到低：

1. **模組自報**：Fabric / Quilt 模組的清單檔案裡寫著自己在哪端執行
2. **平台建置資訊**：Modrinth 與 CurseForge 上這一份建置的官方聲明（經鏡像查詢，無需 Key）
3. **專案級聲明**：模組作者在平台上對整個專案的說明
4. **整合包自帶聲明**：打包者寫進整合包的環境說明（整表明顯敷衍時會作廢這一層）
5. **名稱特徵**：以上都沒有時，按檔名的常見特徵兜底（如光影、小地圖）

## 三種結果

| 結果 | 含義 |
| --- | --- |
| 保留 | 有依據說明伺服器需要它 |
| 剔除 | 有依據說明它是用戶端專屬 |
| 待人工確認 | 沒有任何來源能回答——預設放進剔除分組並標黃，**由你決定去留** |

「待人工確認」是刻意的設計：寧可多問你一句，也不靜默地把模組刪掉或留下。

## 兩個保護機制

- **矛盾會標出來**：兩個來源說法不一致的模組會標上「結論有衝突」，提醒你親自看一眼
- **依賴不會被誤刪**：被保留模組依賴的基礎庫，即使被標記為用戶端專屬也會強制保留並標出

## 你的改判永遠優先

自動結論只是草案。每一行都可以手動改判，建置嚴格按你確認後的方案執行。
關掉「自動剔除用戶端專屬資源」後，應用只給證據、不做任何自動剔除。
