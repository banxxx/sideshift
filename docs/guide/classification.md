# 自动分类

「这个模组服务端要不要装」是转换的核心问题。SideShift 从多个来源收集证据，
按可信度取最可靠的一条作为结论——**没有任何依据时绝不猜**。

## 证据从哪来

按可信度从高到低：

1. **模组自报**：Fabric / Quilt 模组的清单文件里写着自己在哪端运行
2. **平台构建信息**：Modrinth 与 CurseForge 上这一份构建的官方声明（经镜像查询，无需 Key）
3. **项目级声明**：模组作者在平台上对整个项目的说明
4. **整合包自带声明**：打包者写进整合包的环境说明（整表明显敷衍时会作废这一层）
5. **名称特征**：以上都没有时，按文件名的常见特征兜底（如光影、小地图）

## 三种结果

| 结果 | 含义 |
| --- | --- |
| 保留 | 有依据说明服务端需要它 |
| 剔除 | 有依据说明它是客户端专属 |
| 待人工确认 | 没有任何来源能回答——默认放进剔除分组并标黄，**由你决定去留** |

「待人工确认」是刻意的设计：宁可多问你一句，也不静默地把模组删掉或留下。

## 两个保护机制

- **矛盾会标出来**：两个来源说法不一致的模组会标上「结论有冲突」，提醒你亲自看一眼
- **依赖不会被误删**：被保留模组依赖的基础库，即使被标记为客户端专属也会强制保留并标出

## 你的改判永远优先

自动结论只是草案。每一行都可以手动改判，构建严格按你确认后的方案执行。
关掉「自动剔除客户端专属资源」后，应用只给证据、不做任何自动剔除。
